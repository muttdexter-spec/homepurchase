# First House: operating manual

The workflow around the analysis. Updated 2026-09-06 for v2, after the 2450 Overton failure.
Companion to `claude/photo-reno-grading-handoff.md` (what the analysis does) and
`claude/search-harvest.md` (how the crawl works).

**Superseded content removed.** Earlier versions of this file suggested clicking accordion headers to
expand listing sections. That is wrong and harmful: on the ITSO account it triggers an "Unlock The
Full Experience" gate. The correct method reads the DOM directly with no clicking except "Read More".
See `search-harvest.md` Part 2.

---

## 0. The current process, and its four problems

What was being done: manually expand every section, print to PDF, save as the address, collect URLs
separately, then send URLs plus a spec to run photo analysis, then run a grading prompt.

**Steps 1 to 3 are three passes over one web page.** Every field in that PDF is already in the DOM
when you print it, and so are the photo links. One visit does all of it.

**The PDF is the wrong input.** It is a lossy render of structured data that then has to be parsed
back into structure. The `ISP_ACCORDION_COLLAPSED` and `ROOM_TABLE_BLANK` flags in the old grading
file are the manual expansion failing silently and the parse inheriting the damage. Keep PDFs as
archive, not source.

**Batch shape, streaming input.** Listings arrive continuously. Intake and ranking have completely
different costs and must never run together.

**Nothing fed back.** The A-graded houses were walked, found poor, and that information stayed in
someone's head. That is how Overton graded B.

## 1. Three loops at different cadences

| Loop | Trigger | Cost | Repeats |
|---|---|---|---|
| **Intake** | New listing | Expensive: full coverage plus full-resolution condition pass | **Once per listing, ever** |
| **Ranking** | Any time | Nearly free: a script over CSVs | Constantly |
| **Feedback** | After every showing | 2 minutes | Every showing |

Intake is expensive and permanent. Ranking is free. Never conflate them. This separation is what
makes v2's higher photo cost survivable: you pay it once per property in its life, then retune the
cost model as often as you like for nothing.

## 2. Intake

One browser session per listing. No manual expansion, no print dialog, no sign-in.

```
1. Navigate with the matching board token
2. __intake()                     → data.json      (search-harvest.md Part 2)
3. Coverage sheets at 128px       → photo inventory, room index map
4. Full-width single photos 760px → every condition call  (analysis spec section 4)
5. Manipulation checks            → photo-manipulation.md
6. Write observations.json, append to listings_observed.csv
7. Optionally print PDF as archive
```

Details before photos, always. The contact-sheet renderer rewrites `document.body`.

**Do not filter the photo selector on `naturalWidth`.** Gallery images are lazy-loaded and report 0.
Corrected snippet in `testrun-overton.md` section 5.

## 3. Folder structure

### The live bug to fix first

Filenames use three conventions, and the address column disagrees between files: `1432 Dewbourne` in
one, `1432 DEWBOURNE Crescent` in another. Joins will silently drop rows, and a dropped row looks
exactly like a listing that never qualified.

**Key on the MLS number.** The card view exposes it directly. It is unambiguous, it is what your
agent and lawyer use, and a terminate-and-relist produces a new MLS for the same address, which is how
you detect that trick. Keep a slug as a folder name; never join on it.

```
~/FirstHouse/
  listings/                      # APPEND-ONLY. Never regenerated.
    bur-2450-overton/
      source.pdf  data.json  observations.json  notes.md
  data/                          # DERIVED. Delete and rebuild freely.
    listings.csv  sold.csv  ceilings.csv  queue.csv
  config/
    cost_model.yaml              # every tunable number, none in code
    priority.yaml                # queue ordering, never exclusion
  scripts/
    intake.py  grade.py
  reports/
    showing-checklists.md  agent-questions.md
```

Three rules that matter more than the layout:

1. **`listings/` is append-only.** A model change must never cost you a re-crawl. At v2 photo prices
   this is the difference between a ten-second re-rank and a week.
2. **`data/` is disposable.** Regenerated by script. Never hand-edit.
3. **Every tunable number in `config/`.** Changing a kitchen estimate is a YAML edit and a free
   re-rank, not a conversation about a Python script.

## 4. Queue ordering, never filtering

Every agent-filtered listing gets intaken and fully reviewed. Only the order varies.
`config/priority.yaml` scores incoming listings on price fit, beds, lot, DOM and whether the remarks
suggest condition worth investigating. Promising listings get looked at within hours instead of at
the end of a batch. Nothing is ever removed for being unpromising.

---

## 5. Automate the trigger

A weekday-morning scheduled task that re-harvests both saved searches, diffs against the queue,
intakes anything new, re-ranks, and sends a short summary. You stop checking.

It needs the laptop online with the desktop app running, and it will miss mornings when the machine
sleeps, so it sits behind your saved-search email alerts rather than replacing them.

## 6. What you are currently throwing away

**Price history and original list price.** A listing at $1.19M that opened at $1.25M fifty days ago
is a different proposition from a fresh $1.19M, as both a quality signal and a negotiating position.

**Terminate-and-relist.** Detectable once you key on MLS and append.

**Status badges.** `Back on Market`, `Price Decrease`, `New Listing` are on the search cards and are
transient. Capture at harvest. Two current listings are Back on Market, meaning a firm deal collapsed
— usually a failed inspection, financing, or a buyer walking during conditions.

**Sold prices, as tracked listings go firm. The most valuable item in this document.**

You have no sold comps, which is why after-renovation value is blocked and every neighbourhood
ceiling is provisional. But you are already watching your exact target segment. Check status monthly,
record sold prices, and in two or three months you have fifty to a hundred real comps in your precise
band, each with your own condition observations attached. That is a better comp set than anything you
can request at offer stage, and it is what turns "this reno costs $180k" into "this reno costs $180k
and the street tops out $150k above where you would be."

Regenerate `data/ceilings.csv` monthly. Start recording now, while it still feels useless.

## 7. The feedback loop

`listings/<slug>/notes.md` after every showing:

```markdown
visited: <date>
model verdict: <>          my verdict: <>
model reno_planning_p80: $<>   my gut: $<>
what the photos hid entirely:
what the model got right:
walk-away reason:
would buy at:
```

**Track one number: your gut estimate divided by the model's p80.** If it stays above 1.0, the
provisions in section 6 of the analysis spec are still too soft. That ratio is the direct, measurable
test of whether the Overton problem is fixed, and it is the only one that matters.

Every five to ten showings, ask which schema field caused each miss. Three misses tracing to one
field is a fixable defect rather than a vague sense that the model is off.

## 9. Cost and time

**Your time:** about three and a half minutes per listing today for expanding, printing, naming and
URL collection. At ten new listings a week that is thirty-five minutes of clerical work that gets
skipped when you are busy, which is how listings go unanalysed. After: effectively zero.

**Tokens**, order of magnitude:

- Intake with v2 full-resolution condition pass: **100k to 180k Sonnet per listing**, once ever
- Re-rank the whole pool: a few thousand. Run it freely
- First batch of 25: roughly **3M to 4.5M Sonnet tokens**, one time
- Steady state at ten new listings a week: roughly **1.2M a week**

That is 2.5x v1, and it is what the mandate not to underestimate actually costs. The Overton run is
what it buys.

## 10. Offer-stage readiness

- **Line up a home inspector now.** Good Halton inspectors book out, and the one time you need one is
  the one time you cannot wait.
- Have the comps request ready for your agent. By then `sold.csv` should have something to say too.
- Fuse panel, knob-and-tube, or an unpermitted suite: get an insurance quote **before** the offer.
  Insurability is a real gate on older Halton stock and it gets discovered too late.
- If it is a project, have the Purchase Plus Improvements conversation with your broker in advance so
  you know whether it is available and on what terms. Confirm with the broker, not this document.
  None of this is financial advice.
- Verify permits for any finished basement, second unit or addition before the offer, not during
  conditions. Where a legal suite is part of the value case, this is not optional.
